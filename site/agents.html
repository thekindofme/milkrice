Connect your agents

Read-only access to your meetings, set up with one line per agent.

Milkrice gives agents three things: the milkrice command, an MCP server (milkrice mcp, five read-only tools) and a skill that teaches agents to use them. Everything an agent reads is labelled as NOTES (what you typed), AI SUMMARY (written by a named model) or TRANSCRIPT (speech-to-text), so it never mistakes a model's summary for something you wrote. Nothing leaves your Mac unless your agent sends it to its own model.

First, install Milkrice. Homebrew also puts milkrice on your PATH:

brew install --cask thekindofme/tap/milkrice

If you'd rather not use a terminal, open Milkrice, go to Settings → Agents and press Connect next to your agent. It installs the milkrice command too.

Claude Code

Install the plugin. It adds the MCP server and the skill, and updates with Milkrice releases:

claude plugin marketplace add thekindofme/milkrice
claude plugin install milkrice@milkrice

Inside a Claude Code session, the same thing is /plugin marketplace add thekindofme/milkrice followed by /plugin install milkrice@milkrice.

Or register it directly, without the plugin. Use one or the other, not both:

milkrice agents install claude

Then ask something like “what did we decide in yesterday's design sync?”

Codex

Registers the MCP server in ~/.codex/config.toml and installs the skill in ~/.agents/skills:

milkrice agents install codex

MCP only, with Codex's own command:

codex mcp add milkrice -- milkrice mcp

Cursor

Adds Milkrice to ~/.cursor/mcp.json (your other servers stay as they are) and installs the skill:

milkrice agents install cursor

Or Add to Cursor — this one runs milkrice from your PATH, so it needs the Homebrew install.

OpenCode

Adds Milkrice to OpenCode's global config (~/.config/opencode/opencode.json) and installs the skill in ~/.agents/skills, which OpenCode reads:

milkrice agents install opencode

VS Code (GitHub Copilot)

Adds Milkrice to Copilot's global MCP config (~/.copilot/mcp-config.json) and the skill to ~/.copilot/skills:

milkrice agents install vscode

MCP only, with VS Code's own command:

code --add-mcp '{"name":"milkrice","type":"stdio","command":"milkrice","args":["mcp"]}'

Other agents

Many agents that run shell commands read skills from ~/.agents/skills. This installs the skill there (and in ~/.claude/skills):

milkrice agents install skill

To put the skill somewhere else, milkrice skill prints it.

Any MCP client

Milkrice's MCP server runs over stdio. Most clients take a block like this:

mcp.json
{
  "mcpServers": {
    "milkrice": {
      "command": "milkrice",
      "args": ["mcp"]
    }
  }
}

Apps opened from the Dock may not see your shell's PATH. If yours can't start milkrice, use the full path that milkrice agents status prints, such as /opt/homebrew/bin/milkrice.

The tools are list_meetings, list_folders, get_meeting, get_transcript and search, all marked read-only.

Check and undo

See what's connected, where each entry lives, and anything that needs fixing:

milkrice agents status

Connect every agent Milkrice finds, or remove everything it added:

milkrice agents install all
milkrice agents uninstall all
  • Only its own entry. The installer adds or removes the milkrice entry and leaves everything else in your config files alone.
  • Backups. Before it changes an existing file, it saves a copy next to it as <file>.milkrice-backup-<time>.
  • Safe to repeat. Running an install again changes nothing. Add --dry-run to see what would change.
  • PATH. Without Homebrew, milkrice goes in ~/.local/bin, which a new zsh doesn't include. milkrice agents status says when that's the case and how to fix it. MCP works either way, because it's registered with the full path.
  • Who can read your meetings. The MCP server talks only to the agent that started it, over stdio; it opens no port. Any program running as you could already read Milkrice's files, so your Mac user account is what protects them.
