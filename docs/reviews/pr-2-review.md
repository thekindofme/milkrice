## Findings

### 1. Medium: Return during Japanese/Chinese/Korean input leaves the title (WebKit IME quirk)
`ui/app.js:966`: `if (e.key === "Enter" && !e.isComposing) { … title.blur(); }`

Milkrice runs in WKWebView. WebKit fires `compositionend` **before** the `keydown` for the Return that commits an IME candidate, so that keydown has `isComposing === false` (with `keyCode === 229`). Users typing a title in Japanese, Chinese or Korean have the field blur on every candidate commit, and then have to click back in to keep typing.
**Fix:** `if (e.key === "Enter" && !e.isComposing && e.keyCode !== 229)`, or track composition with `compositionstart`/`compositionend` and ignore the Enter that follows within the same tick.

### 2. Low: the height is wrong until a resize if the layout or font isn't ready when `fitTitle` runs
`ui/app.js:964` (`fitTitle(title)` in `bindNote`) and `:952` (window `resize` only)

`scrollHeight` is read synchronously right after the HTML is injected. If the serif face ("New York") isn't loaded yet, or the column width changes without a window resize (the sidebar or chat pane toggling, the settings→note transition), the textarea keeps a stale height. A 1-line height on a title that wraps to 2 lines clips the second line, which is the bug this PR is fixing.
**Fix:** use a `ResizeObserver` on `.note-head` (or the textarea) instead of `window.resize`, and call `document.fonts.ready.then(() => fitTitle($("#titleInput")))` once.

### 3. Low: pasting multi-line text moves the caret to the end
`ui/app.js:968`: assigning `title.value` resets the selection. Pasting "foo\nbar" into the middle of a title leaves the caret at the end.
**Fix:** save `selectionStart`, adjust it for the removed characters, and restore it. Or handle it in `onpaste`/`beforeinput` (`inputType === "insertLineBreak" || "insertParagraph"`, then `preventDefault()`) and insert the cleaned text with `setRangeText`.

### 4. Nit: the newline-collapsing regex leaves a trailing space when the pasted text ends in a newline
`/\s*[\r\n]+\s*/g` → `" "`, so "Title\n" becomes "Title " and that is saved. Use `.replace(/\s*[\r\n]+\s*/g, " ").replace(/^ | $/g, "")` only on the pasted part, or trim when the title is saved.

### 5. Nit: titles saved earlier with embedded newlines (calendar SUMMARY, LLM-suggested titles) now show as multiple lines until edited
Previously `<input>` collapsed them. Normalise when rendering (`esc(m.title.replace(/\s*\n\s*/g, " "))`) so display and editing match.
